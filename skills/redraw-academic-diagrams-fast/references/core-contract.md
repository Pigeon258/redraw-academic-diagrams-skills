# Core Contract

## Must remain editable

- visible text;
- containers and cards;
- semantic module groups;
- relationships;
- user-changeable chart bars, nodes, or repeated elements.

## Atomic SVG boundary

Use SVG for any atomic icon whose internal content will not be edited. Use one compatible family across a page. Do not mix imported SVG icons with temporary hand-drawn semantic icons.

Simple custom SVG is acceptable when it is:

- plain vector XML;
- conceptually correct;
- consistent with the page family;
- stable in Microsoft PowerPoint;
- recorded as task-local work.

## Grouping

Group each semantic module for whole-module movement. Preserve useful internal editing. Avoid a page-wide monolithic group and avoid hundreds of unrelated top-level parts.

## Connectors

Every visible relationship is one native connector or arrow line. Use an elbow connector for a continuous folded route. Do not assemble arrows from multiple lines and an independent head.

Binding is optional when it harms the intended route. Correct appearance and easy reconnection are more valuable than forced binding.

## Fast non-negotiables

The following cannot be deferred to a user fixlist:

- unreadable or materially wrong key text;
- unresolved high-impact semantic ambiguity;
- broken PowerPoint file;
- flattened core content;
- missing semantic module grouping that makes ordinary edits impractical;
- systemic SVG-family failure;
- fake multi-part arrows;
- widespread or hidden relationship errors.

One obvious, local, non-cascading omission may qualify for `FAST PASS WITH FIXLIST`; a pattern of omissions does not.
