# Fast Workflow

## F0 — Scope and cap

Confirm the exact source, target slide count, Microsoft PowerPoint output, requested semantic changes, and a short time cap. Ask only questions that can change meaning, structure, or delivery state.

## F1 — Compact inventory

Write short working notes, not a long plan:

- major regions and reading order;
- semantic modules and module titles;
- editable text;
- atomic SVG icons;
- charts or repeated native elements;
- relationships as source, target, direction, level, and route.

Do not inventory decorative micro-elements individually unless they affect layout.

## F2 — Method and assets

Reuse verified code primitives and one SVG family. For an unfamiliar high-risk structure, prototype only the smallest representative slice and abandon a failing method quickly.

Asset order:

1. already verified same-family SVG;
2. small search in a license-clear library;
3. simple custom SVG in the same visual grammar;
4. recorded near-meaning substitute;
5. user decision for high-impact ambiguity.

Do not continue searching for a theoretically perfect icon after a contract-satisfying option exists.

## F3 — Build and integrate

Create cross-module connectors before the final node/card layer when practical. Build modules with stable names and one useful group. Keep cross-module connectors outside module groups.

Integrate once:

- align region boundaries;
- normalize spacing, font family, color, line weight, and icon scale;
- verify relationship levels and directions;
- avoid reworking already acceptable regions.

## F4 — Minimum QA

Perform one combined pass:

- source and user-change comparison;
- complete-page readability;
- `inspect_pptx.py`;
- `inspect_svg.py` when applicable;
- PowerPoint open/save/reopen;
- representative text, module, connector, and SVG edits when applicable.

If automation is unavailable, use the minimum reliable substitute and record the gap. Do not pretend an unrun check passed.

## F5 — Deliver

Deliver:

- one PPTX;
- one matching preview;
- practical state;
- a concise fixlist when needed.

Do not deliver build directories, source images, detailed QA reports, or asset ledgers unless requested.

## F6 — Iterate

Classify feedback by scope. Preserve unaffected modules and accepted versions. A user edit is evidence about real editing cost, not evidence that the first version had no value.

Stop when the user accepts the result, formal `PASS` is reached, `FAST PASS WITH FIXLIST` is appropriate, or the time cap requires a clear scope/status decision.
